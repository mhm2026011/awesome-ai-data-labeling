## 4. Baseline results on real data (label-only)

These use only the real CIFAR-10H annotator file and the original CIFAR-10 test labels. No classifier is involved. Source: `results/label_only.json`, `per_annotator_accuracy.csv`.

### 4.1 Reconciliation with the published files (G-4)

| Quantity | Value | Tag |
|----------|-------|-----|
| Rows in the raw file | 539,910 | VERIFIED |
| Attention-check rows | 25,710 | VERIFIED |
| Real judgments with no exclusion | 514,200 (539,910 - 25,710) | VERIFIED |
| Annotators below 75% on attention checks | 16 of 2,571 | VERIFIED |
| Judgments after excluding them | 511,000, **identical** to `counts.npy` (sum 511,000; 47 to 63 per item) | VERIFIED |

**Discrepancy to flag:** the dataset's documentation page (read in Stage 2) says 14 workers were removed and 511,400 classifications were collected. The released files give 16 removed and 511,000. 2,555 annotators x 200 items = 511,000. Why the page and the files differ is UNKNOWN. My code follows the released files, because that rule reproduces `counts.npy` exactly. Do not quote the 14 or the 511,400 for this analysis.

### 4.2 Reference-label sensitivity (D-020)

| Quantity | Value |
|----------|-------|
| Panel plurality equals the original CIFAR-10 label | 99.21% of items (9,921 of 10,000) |
| Items where they disagree | 79 |
| Plurality ties (broken by lower class index) | 3 |

So the two reference rules differ on under 1% of items (INFERRED: the sensitivity analysis will probably shift accuracies by well under one point; the model arm will show).

### 4.3 Manual arm (G1): one annotator's label per item

| Reference | Mean accuracy over 1,000 random draws | SD | 2.5th to 97.5th percentile |
|-----------|----------------------------------------|----|-----------------------------|
| Original CIFAR-10 label (primary) | 0.9523 | 0.0018 | 0.9488 to 0.9558 |
| Human plurality (sensitivity) | 0.9544 | 0.0019 | 0.9508 to 0.9582 |

A model has to reach about 0.95 to match a single crowd annotator on this set (INFERRED from the table).

### 4.4 Noise floor (G5): annotator-to-annotator spread

| Quantity | Value |
|----------|-------|
| Annotators analysed | 2,555 (each labelled exactly 200 items) |
| Accuracy against the original label: mean | 0.9524 |
| SD | 0.0287 |
| 5th percentile, median, 95th percentile | 0.905, 0.960, 0.985 |

**Reading (INFERRED).** With 200 items and accuracy near 0.95, pure sampling noise would give an SD of about 0.015 (sqrt(0.95 x 0.05 / 200)). The observed SD of 0.029 is about twice that, so annotators genuinely differ, beyond chance. Any model-versus-annotator gap smaller than about 0.03 would sit inside one SD of that spread (this is the comparison H4 will make once the model accuracy exists). I have not computed a formal test of this.

### 4.5 Where single-annotator errors sit

| Items | Count (of 10,000) |
|-------|-------------------|
| Every judgment correct | 4,392 |
| Fewer than 80% of judgments correct | 609 |
| Fewer than 50% of judgments correct | 122 |

**Why it matters for H2 (INFERRED, not tested):** a single annotator's errors are concentrated on about 6% of images. If the model's uncertainty points at those same images, sending them to a single annotator helps little; if it points at images humans find easy, review helps more. The model arm is the test.

## 5. Pipeline check on a real classifier (NOT a Study B result)

Data: scikit-learn's bundled digits (899 test items after a 50/50 split), logistic regression, 10 seeds. Reviewer judgments are **synthetic** (20 per item; each correct with probability 0.9, otherwise a random class). This only shows the code runs end to end and obeys the gates. Digits are not a scientific dataset and say nothing about CIFAR-10H.

Model-only accuracy 0.9608; calibration error 0.0933 (seed 0). At budget 0.20:

| Reviewer | Arm | Accuracy | Gain over random (paired 95% interval) |
|----------|-----|----------|------------------------------------------|
| perfect | random | 0.9677 | - |
| perfect | entropy | 0.9966 | 0.0288 (0.0207 to 0.0385) |
| perfect | margin | 0.9959 | 0.0281 (0.0201 to 0.0378) |
| perfect | oracle | 1.0000 | 0.0323 (0.0234 to 0.0429) |
| single (synthetic) | random | 0.9471 | - |
| single (synthetic) | entropy | 0.9771 | 0.0300 (0.0214 to 0.0399) |
| single (synthetic) | oracle | 0.9791 | 0.0320 (0.0231 to 0.0409) |

The ordering (oracle >= uncertainty arms > random) and the exact oracle formula match what the protocol requires. Source: `results/validate_digits.csv`.

**Synthetic-feature smoke test of `run_model_arm.py`.** The runner was executed on the real CIFAR-10H labels with synthetic features generated from the labels. It completed (3 seeds, 300 bootstrap resamples, about 8 seconds) and wrote both result tables. **No numbers from this run are reported**, because the features were built from the answers and mean nothing. Its timing does not predict the real run.
